# The commit hook cites a document that does not exist, and its twin can drift

## Where it stands

Two closely related facts, both in three lines of shell.

**The citation.** `.githooks/commit-msg` — this repository's own hook — ends its
header with:

```sh
# See CODING_CONVENTIONS.md ("Git").
```

There is no `CODING_CONVENTIONS.md` in the repository. Someone told to look it up
after their commit is rejected finds nothing, and the hook's own header is the
only statement of the rules that exists.

**The twin.** `templates/commit-msg` is the same file with that one line removed —
byte-identical otherwise. It is copied verbatim into every generated project,
where the citation would have been a dangling reference too, so removing it there
was right. But the result is two copies of an executable file, differing by one
line, with nothing checking that the *other* forty stay identical. A fix applied to
one — a new exempt prefix, a change to the subject limit — silently leaves the
other behind, and the divergence shows up as a generated project whose hook
behaves differently from the one this repository uses to enforce the same
convention.

## What to do

**The citation:** either write the document or drop the line. Dropping it is
defensible — the hook's header already lists the four rules completely, and a
document that only restates them is a second place to keep correct. Writing it is
better if there are conventions beyond the commit message worth stating (the
comment style this codebase clearly has, the "explain why, not what" rule its
comments follow, the one-decision-per-commit habit its history shows). Either way,
a header comment must not point at nothing.

**The twin:** make the difference structural rather than remembered. A test in
`internal/generate` that reads both files and asserts the template equals the
repository's hook minus the citation line is four lines long and never wrong. If
the citation goes away, the assertion becomes a plain equality and the two files
can never drift at all.

The stronger version — one file, with this repository pointing `core.hooksPath` at
a directory containing a copy generated by the tool itself — is cute, adds a build
step to a git hook, and is not worth it. The test is the right size for the risk.

## Test

As described: one comparison test in `internal/generate`, beside
`TestSharedFilesAreCopiedVerbatim`, which already reads the template bytes and is
the natural home for it.
